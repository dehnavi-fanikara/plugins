نقش شما:
به‌عنوان یک توسعه‌دهنده ارشد WordPress/PHP با تمرکز بر معماری افزونه، امنیت، کارایی، تجربه کاربری پنل مدیریت، سازگاری RTL و استانداردهای WordPress Coding Standards عمل کن.

یک افزونه وردپرس کامل، production-ready، قابل نصب و قابل توسعه با مشخصات زیر ایجاد کن.

==================================================
1. مشخصات پایه افزونه
==================================================

همجواری مناطق در برچسب

barchasb-area-adjacency

Text Domain:
barchasb-area-adjacency

0.0.1

8.2 یا بالاتر

نوع افزونه:
Standalone WordPress Plugin

زبان اصلی پنل:
فارسی

الزامات:
- سازگاری کامل با سایت‌های RTL
- قابل ترجمه با توابع استاندارد i18n وردپرس

- معماری افزونه شی‌گرا و ماژولار باشد

==================================================
2. هدف اصلی افزونه
==================================================

در سایت دو Custom Post Type با نام‌های زیر وجود دارند:

- karaj_state
- tehran_state

هر پست از این Post Typeها نماینده یک منطقه، محله یا Money Page مرتبط با خدمات یک منطقه است؛ برای مثال:

- جنوب تهران
- شمال تهران
- تهرانپارس
- صادقیه
- مهرشهر کرج
- گوهردشت کرج
- عظیمیه کرج

اپراتور یا مدیر سایت باید هنگام ایجاد یا ویرایش هر پست بتواند مشخص کند چه پست‌ها یا مناطقی به پست جاری نزدیک یا مرتبط هستند.

برای مثال، در صفحه «جنوب تهران» مدیر می‌تواند موارد زیر را به‌عنوان مناطق نزدیک انتخاب کند:

- نازی‌آباد
- خزانه
- شهرری
- جوادیه

سپس در محتوای صفحه «جنوب تهران» یک Shortcode قرار می‌گیرد. این Shortcode باید رابطه‌های ثبت‌شده برای پست جاری را تشخیص دهد و مناطق مرتبط را در قالب یک Carousel زیبا، واکنش‌گرا و قابل اسکرول نمایش دهد.

هر کارت Carousel حداقل باید شامل موارد زیر باشد:

- تصویر شاخص پست مرتبط
- عنوان پست مرتبط
- لینک CTA
- متن قابل تنظیم دکمه CTA
- لینک به صفحه پست مرتبط

روابط نزدیک بودن پست‌ها صرفاً توسط مدیر یا اپراتور سایت تنظیم شوند و به‌صورت خودکار براساس نام، فاصله یا موقعیت جغرافیایی تولید نشوند.

==================================================
3. نقش‌ها و دسترسی‌ها
==================================================

تنظیمات عمومی افزونه فقط برای کاربرانی نمایش داده شود که capability زیر را دارند:

manage_options

متاباکس ارتباط مناطق برای کاربرانی قابل استفاده باشد که دسترسی ویرایش پست جاری را دارند:

current_user_can( 'edit_post', $post_id )

در صفحه تنظیمات افزونه، امکان تعیین capability موردنیاز برای مدیریت روابط وجود داشته باشد.

مقدار پیش‌فرض:

edit_others_posts

اگر کاربر capability لازم را نداشت:

- متاباکس برای او نمایش داده نشود؛ یا
- فیلدهای آن فقط خواندنی باشند، براساس تنظیم انتخاب‌شده در پنل

تمام endpointهای AJAX و REST احتمالی باید موارد زیر را بررسی کنند:

- احراز هویت کاربر
- capability مناسب
- nonce معتبر
- معتبر بودن Post ID
- معتبر بودن Post Type
- معتبر بودن وضعیت پست

==================================================
4. مدیریت Post Typeهای فعال
==================================================

در صفحه تنظیمات افزونه بخشی با عنوان زیر ایجاد شود:

«پست‌تایپ‌های مناطق»

در نسخه اولیه، مقادیر پیش‌فرض این دو Post Type باشند:

- karaj_state
- tehran_state

اما ساختار افزونه نباید به‌صورت hard-coded صرفاً محدود به این دو Post Type باشد.

مدیر بتواند از میان Post Typeهای عمومی و دارای رابط مدیریتی، Post Typeهای موردنظر را فعال یا غیرفعال کند.

تنظیمات پیش‌فرض:

active_post_types = [
    'karaj_state',
    'tehran_state'
]

Post Typeهای داخلی وردپرس مانند موارد زیر در لیست نمایش داده نشوند:

- attachment
- revision
- nav_menu_item
- custom_css
- customize_changeset
- wp_block
- wp_template
- wp_template_part

اگر یکی از Post Typeهای پیش‌فرض در سایت ثبت نشده باشد:

- افزونه نباید خطای Fatal ایجاد کند
- در صفحه تنظیمات یک هشدار مدیریتی نمایش داده شود
- نام Post Type ناموجود در هشدار مشخص شود

==================================================
5. متاباکس «مناطق نزدیک و مرتبط»
==================================================

در صفحات ایجاد و ویرایش پست‌های فعال، یک متاباکس با عنوان زیر اضافه کن:

«مناطق نزدیک و مرتبط»

شناسه متاباکس:

baa_adjacent_areas_metabox

این متاباکس باید برای Post Typeهای فعال در تنظیمات نمایش داده شود.

داخل متاباکس، اپراتور بتواند:

1. Post Type مقصد را انتخاب کند.
2. عنوان پست‌ها را جست‌وجو کند.
3. یک یا چند پست مرتبط را انتخاب کند.
4. ترتیب نمایش آیتم‌های انتخاب‌شده را تغییر دهد.
5. آیتم‌های انتخاب‌شده را حذف کند.
6. وضعیت انتشار هر آیتم را مشاهده کند.
7. Post Type هر آیتم را مشاهده کند.
8. لینک ویرایش آیتم مرتبط را در صورت داشتن دسترسی باز کند.
9. تصویر شاخص کوچک هر آیتم را مشاهده کند.
10. تغییرات را همراه با ذخیره یا به‌روزرسانی پست ذخیره کند.

Post Type مقصد می‌تواند یکی از Post Typeهای فعال باشد. بنابراین:

- یک پست از karaj_state می‌تواند به چند پست karaj_state مرتبط شود.
- یک پست از tehran_state می‌تواند به چند پست tehran_state مرتبط شود.
- در صورت فعال بودن تنظیم مربوطه، ارتباط بین karaj_state و tehran_state نیز مجاز باشد.

در متاباکس یک راهنمای کوتاه فارسی نمایش داده شود:

«مناطقی را انتخاب کنید که از نظر محتوایی یا جغرافیایی به صفحه جاری نزدیک هستند. این موارد در محل قرارگیری شورت‌کد، به‌صورت اسلایدی برای بازدیدکنندگان نمایش داده می‌شوند.»

--------------------------------------------------
5.1. رابط انتخاب آیتم‌ها
--------------------------------------------------

از بارگذاری هم‌زمان همه پست‌ها در HTML صفحه جلوگیری کن؛ زیرا ممکن است تعداد پست‌ها زیاد باشد.

به‌جای آن، جست‌وجوی AJAX با تأخیر Debounce پیاده‌سازی شود.

ویژگی‌های جست‌وجو:

- حداقل تعداد کاراکتر پیش‌فرض برای شروع جست‌وجو: 2
- تعداد نتایج هر درخواست: 20
- قابلیت Pagination
- جست‌وجو در عنوان پست
- جست‌وجو در Post ID در صورت عددی بودن عبارت
- فیلتر براساس Post Type انتخاب‌شده
- حذف پست جاری از نتایج
- جلوگیری از نمایش آیتم‌های تکراری
- عدم نمایش پست‌های trash و auto-draft
- نمایش وضعیت پست برای آیتم‌های غیرمنتشرشده
- نمایش تصویر شاخص کوچک در نتایج، در صورت موجود بودن

برای رابط کاربری می‌توان از یکی از این روش‌ها استفاده کرد:

- WordPress Components
- یک کامپوننت سبک اختصاصی
- Select2 یا Tom Select به‌صورت local bundled

استفاده از CDN ممنوع است.

--------------------------------------------------
5.2. مرتب‌سازی روابط
--------------------------------------------------

لیست آیتم‌های انتخاب‌شده باید Drag & Drop باشد.

ترتیب ذخیره‌شده دقیقاً همان ترتیب پیش‌فرض نمایش در Carousel باشد.

برای مرتب‌سازی از یک کتابخانه سبک محلی یا امکانات موجود وردپرس استفاده شود.

دکمه‌های جایگزین برای دسترس‌پذیری نیز اضافه شوند:

- انتقال به بالا
- انتقال به پایین
- حذف

--------------------------------------------------
5.3. ذخیره روابط
--------------------------------------------------

روابط در post meta پست مبدأ ذخیره شوند.

Meta Key پیشنهادی:

_baa_adjacent_post_ids

مقدار ذخیره‌شده یک آرایه مرتب‌شده از IDهای عددی و یکتا باشد:

[
    125,
    198,
    233
]

قبل از ذخیره:

- nonce بررسی شود
- autosave نادیده گرفته شود
- revision نادیده گرفته شود
- capability بررسی شود
- Post Type پست جاری معتبر باشد
- تمام IDها با absint پاک‌سازی شوند
- IDهای تکراری حذف شوند
- ID پست جاری حذف شود
- فقط Post Typeهای مجاز پذیرفته شوند
- ترتیب انتخاب اپراتور حفظ شود

در صورت خالی بودن انتخاب‌ها:

delete_post_meta()

استفاده شود و meta خالی ذخیره نشود.

Meta به‌صورت زیر ثبت شود:

register_post_meta()

تنظیمات پیشنهادی:

- type: array
- single: true
- show_in_rest: true
- auth_callback امن
- sanitize_callback اختصاصی

==================================================
6. نوع رابطه
==================================================

در تنظیمات افزونه گزینه‌ای با عنوان زیر ایجاد کن:

«نوع ارتباط مناطق»

گزینه‌ها:

1. یک‌طرفه
2. دوطرفه خودکار

مقدار پیش‌فرض:

یک‌طرفه

تعریف رابطه یک‌طرفه:

اگر A به B مرتبط شود، فقط در صفحه A، آیتم B نمایش داده می‌شود. انتخاب A در روابط B به‌صورت خودکار انجام نمی‌شود.

تعریف رابطه دوطرفه:

اگر A به B مرتبط شود، A نیز به روابط B اضافه شود.

برای روابط دوطرفه موارد زیر رعایت شوند:

- ایجاد Loop در عملیات ذخیره رخ ندهد
- ترتیب روابط موجود در پست مقصد خراب نشود
- رابطه جدید در انتهای لیست مقصد اضافه شود
- آیتم تکراری اضافه نشود
- در صورت حذف رابطه، رفتار حذف رابطه معکوس قابل تنظیم باشد

گزینه تنظیماتی دیگری اضافه شود:

«با حذف رابطه، رابطه معکوس نیز حذف شود»

مقدار پیش‌فرض:

فعال

ذخیره رابطه دوطرفه باید idempotent باشد؛ یعنی چند بار ذخیره یک داده، نتیجه تکراری یا ناسازگار ایجاد نکند.

==================================================
7. شورت‌کد اصلی
==================================================

Shortcode اصلی افزونه:

[baa_adjacent_areas]

این Shortcode در حالت پیش‌فرض باید Post ID صفحه جاری را از get_the_ID() دریافت کند، روابط ذخیره‌شده را بخواند و Carousel را نمایش دهد.

نمونه استفاده:

[baa_adjacent_areas]

پارامترهای قابل پشتیبانی:

[baa_adjacent_areas
    post_id="123"
    title="مناطق نزدیک"
    limit="12"
    orderby="manual"
    show_image="yes"
    show_title="yes"
    show_excerpt="no"
    show_cta="yes"
    cta_text="مشاهده خدمات این منطقه"
    slides_desktop="4"
    slides_tablet="2"
    slides_mobile="1"
    autoplay="no"
    loop="no"
    navigation="yes"
    pagination="yes"
]

پارامترهای Shortcode:

- post_id:
  ID پستی که روابط آن باید نمایش داده شود؛ پیش‌فرض پست جاری

- title:
  عنوان بالای Carousel؛ در صورت خالی بودن از تنظیمات عمومی خوانده شود

- limit:
  حداکثر تعداد آیتم‌های قابل نمایش

- orderby:
  یکی از مقادیر:
  manual
  title
  date
  rand

- show_image:
  yes یا no

- show_title:
  yes یا no

- show_excerpt:
  yes یا no

- show_cta:
  yes یا no

- cta_text:
  متن دکمه CTA

- slides_desktop:
  تعداد کارت‌ها در دسکتاپ

- slides_tablet:
  تعداد کارت‌ها در تبلت

- slides_mobile:
  تعداد کارت‌ها در موبایل

- autoplay:
  yes یا no

- autoplay_delay:
  برحسب میلی‌ثانیه

- loop:
  yes یا no

- navigation:
  yes یا no

- pagination:
  yes یا no

- space_between:
  فاصله بین کارت‌ها برحسب پیکسل

- image_size:
  نام image size وردپرس، مانند medium_large

- class:
  کلاس CSS سفارشی

مقادیر Shortcode فقط باید تنظیمات همان نمونه را Override کنند.

اولویت تنظیمات:

1. پارامترهای Shortcode
2. تنظیمات عمومی افزونه
3. مقادیر پیش‌فرض افزونه

==================================================
8. منطق واکشی پست‌های مرتبط
==================================================

برای واکشی پست‌ها:

- ترتیب دستی ذخیره‌شده حفظ شود.
- در حالت manual از post__in و orderby => post__in استفاده شود.
- فقط IDهای معتبر واکشی شوند.
- پست جاری نمایش داده نشود.
- به‌صورت پیش‌فرض فقط پست‌های publish نمایش داده شوند.
- Post Type آیتم‌ها اعتبارسنجی شود.
- suppress_filters به‌صورت ناسازگار با افزونه‌های چندزبانه تنظیم نشود.
- از Query غیرضروری جلوگیری شود.
- در انتهای WP_Query از wp_reset_postdata() استفاده شود.
- اگر تعداد نتایج صفر بود، خروجی خالی یا پیام قابل تنظیم نمایش داده شود.

اگر یک پست مرتبط:

- حذف شده باشد
- به Trash منتقل شده باشد
- Draft شده باشد
- دسترسی عمومی نداشته باشد
- Post Type آن غیرفعال شده باشد

در Front-end نمایش داده نشود، اما در متاباکس مدیریت وضعیت آن مشخص شود تا اپراتور بتواند آن را حذف یا اصلاح کند.

==================================================
9. طراحی Carousel
==================================================

خروجی Shortcode باید یک Carousel مدرن، زیبا و واکنش‌گرا باشد.

کتابخانه پیشنهادی:

Swiper.js

الزامات:

- فایل‌های Swiper به‌صورت Local داخل افزونه قرار بگیرند
- عدم استفاده از CDN
- اسکریپت و استایل فقط در صفحاتی بارگذاری شوند که Shortcode واقعاً استفاده شده است
- چند Carousel در یک صفحه بدون تداخل کار کنند
- برای هر Carousel یک شناسه یکتا ایجاد شود
- پشتیبانی کامل از RTL
- قابلیت Drag/Swipe با ماوس و لمس
- پشتیبانی از Keyboard Navigation
- دکمه قبل و بعد
- Pagination اختیاری
- Autoplay اختیاری
- توقف Autoplay هنگام Hover در صورت فعال بودن تنظیم مربوطه
- رعایت prefers-reduced-motion
- عدم فعال‌سازی Loop در صورتی که تعداد آیتم‌ها برای Loop کافی نیست
- ارتفاع کارت‌ها تا حد ممکن یکسان باشد
- از Layout Shift غیرضروری جلوگیری شود

Breakpoints پیش‌فرض:

- موبایل کمتر از 640px: یک کارت
- تبلت 640px تا 1023px: دو کارت
- دسکتاپ از 1024px: چهار کارت

در صورت وجود تعداد کمتر آیتم نسبت به slidesPerView، Carousel نباید ظاهر خراب یا فضای نامناسب ایجاد کند.

==================================================
10. ساختار کارت‌ها
==================================================

هر کارت دارای ساختار معنایی مشابه زیر باشد:

<section class="baa-adjacent-areas">
    <h2 class="baa-section-title">مناطق نزدیک</h2>

    <div class="baa-carousel swiper" id="baa-carousel-{unique-id}">
        <div class="swiper-wrapper">
            <article class="baa-card swiper-slide">
                <a class="baa-card__image-link" href="...">
                    <img ...>
                </a>

                <div class="baa-card__content">
                    <h3 class="baa-card__title">
                        <a href="...">عنوان منطقه</a>
                    </h3>

                    <div class="baa-card__excerpt">
                        توضیح کوتاه اختیاری
                    </div>

                    <a class="baa-card__cta" href="...">
                        مشاهده خدمات این منطقه
                    </a>
                </div>
            </article>
        </div>

        <button class="baa-carousel__prev">...</button>
        <button class="baa-carousel__next">...</button>

        <div class="baa-carousel__pagination"></div>
    </div>
</section>

الزامات HTML:

- استفاده از تگ‌های semantic
- escape کردن URLها با esc_url()
- escape کردن متن‌ها با esc_html()
- escape کردن attributeها با esc_attr()
- استفاده از wp_kses_post() برای HTML کنترل‌شده
- عنوان لینک‌ها قابل فهم باشد
- دکمه‌های Carousel دارای aria-label فارسی باشند
- تصویر دارای alt مناسب باشد
- در صورت خالی بودن alt تصویر، عنوان پست به‌عنوان fallback استفاده شود
- تصاویر از توابع استاندارد وردپرس مانند get_the_post_thumbnail() ساخته شوند
- تصاویر دارای lazy loading باشند
- عرض و ارتفاع تصویر برای کاهش CLS ثبت شود

در صورت نداشتن تصویر شاخص:

- تصویر پیش‌فرض قابل تنظیم نمایش داده شود؛ یا
- براساس تنظیم مدیر، بخش تصویر کاملاً حذف شود

هیچ تصویر شکسته‌ای نمایش داده نشود.
